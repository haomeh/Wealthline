# 每月收支核對與報表

收支總覽把信用卡與獨立銀行流水放在同一個可追溯的視圖。點月份圖表、收入／消費／差額或分類，可查看來源明細與計算依據，再前往原始紀錄編輯；「返回收支明細」保留月份、分類、來源與分頁。每頁最多顯示 100 筆，合計涵蓋篩選後所有紀錄。

## 金額與證據

信用卡退款保留負數。銀行收入以入帳為正、沖銷支出為負；銀行消費以支出為正、退款入帳為負。不計收支的轉帳或繳卡費仍可查閱，但不加入收入或消費。銀行未分類仍按方向暫計，信用卡未分類屬消費；零金額保留原分類及來源歸屬。分類優先順序為手動指定、自訂第一個匹配規則、內建規則、未分類。

沒有觀測紀錄的月份是未知（JSON `null`／畫面無紀錄），不是零。有觀測紀錄且淨額為零才顯示零；人工確認無活動不會捏造零元紀錄。圖表可先用摘要顯示，但核對及完整報表必須等所有收支明細成功載入。

外幣依各月月底已完成歷史匯率換算 TWD；當月依計算當天最新已完成報價，最多回溯 7 日。報表保留目標日期、實際報價日期、匯率及換算路徑，TWD 採 1。任一必要匯率缺失時，不匯出部分合計。原始貢獻保留機器精度；顯示固定兩位小數並列四捨五入調整，因此逐筆顯示值與合計可核對。資產頁手動匯率不替代這個月度歷史口徑。

## 人工核對

在「每月核對」設定預期銀行帳戶及信用卡來源。銀行使用穩定帳戶 ID；信用卡使用完整標籤原文，空白及大小寫不同就屬不同來源，不會自動合併。可複製上月的預期來源，但不會複製上月確認。

逐來源檢查後確認已核對；零筆來源可確認本月無活動。保留未分類需要填寫最多 500 字的原因。編輯原因只是畫面草稿，必須重新確認來源才套用，再按既有「儲存變更」保存。當月只表示「截至目前已核對」，未來月份不能確認。

人工核對表示使用者檢查過所選來源，**不是銀行帳單完整性證明**。遺漏尚未匯入的交易仍可能存在；已觀測但未列入預期的來源會阻擋整月已核對狀態。資料變更（日期、金額、分類／規則、來源標籤、預期來源清單等）會使相關確認成為「需重新核對」，不刪除舊確認。跨月移動影響移出及移入月份；無關月份與單純匯率更新不使交易核對失效。載入失敗、儲存中或帳號／資料切換時不能完成過時確認。

## 報表與備份

「每月報表」可產生目前資料預覽；包含未儲存修改會明確標示，不能下載。JSON／CSV 匯出要求完整且已儲存的收支明細。未核對或已過時月份仍可匯出，但保留狀態及警示，不能當成已核對。

JSON `wealthline-monthly-report`、`formatVersion: 1`、`policyVersion: 1` 保存選定月份的逐筆貢獻、分類依據、來源、相關銀行標籤、計算日期 `asOfDate`、產生時間、來源資料版本、人工確認及當時狀態、FX、分類與整月合計、捨入調整、SHA-256 指紋。指紋供偵測內容變動，不是簽章、身分驗證或防偽保證。重新產生時間本身不改內容指紋；匯率更新則可能改變金額及指紋。

CSV 供試算表閱讀，保留原始與顯示金額及警示，文字欄位有公式前綴防護。JSON 可重新開啟成獨立唯讀快照：不查即時匯率、不覆寫帳本、不作備份還原。當前紀錄變動或被刪除時，舊快照維持原樣並提示差異。未知格式／政策、雜湊或計算不一致的檔案會拒絕。

月報只涵蓋選定月份，**不能代替完整資料備份**。需搬移資料時使用「下載完整備份」及本機模式還原流程，不要下載 Drive 分檔主檔當作完整備份。核對資料使用 schema v16，保存在主資料檔，不混入流水分檔；清空核對仍不降版。支援上限為 v15 的舊客戶端會拒絕 v16，請更新客戶端後再開啟。現版仍可讀取 v1–v15，讀取本身不自動寫回。

## 驗證範圍

自動測試使用合成資料、fake Drive、jsdom，涵蓋摘要到明細載入、分類與返回、核對儲存、跨月過時、FX 更新、JSON 快照及本機完整還原。瀏覽器檢查也只使用合成資料。這些結果不證明真實 Google Drive 授權、供應商條件寫入語意、任何銀行帳單完整性或正式部署；詳見 [資料安全驗證](data-safety-validation.md)。
