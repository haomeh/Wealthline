# 銀行對帳單與統一收支

銀行流水使用獨立的「銀行／帳戶標籤」，不強制綁定資產帳戶。只記錄確認的入出帳日期、摘要、幣別、方向、非負金額、分類與不可逆去重識別碼；不保存期初／期末／逐筆餘額，也不推算或修改資產、負債、持倉歷史。信用卡消費表格維持原來的資料來源。

## 匯入與保存

銀行 PDF 在本機瀏覽器讀取，以經驗證的表頭／欄位位置取得明確入出帳金額，不把列尾餘額、外匯參考數字或對手帳號當作金額。銀行路徑不套用信用卡專用的匯豐篩選或商家 OCR。文字版 PDF 限制20MB、100頁、500000字元；掃描／不明版型不猜測交易。

各銀行帳戶／幣別區段需選擇既有獨立帳戶標籤，或新增標籤；不能只靠銀行名稱合併不同戶的流水。預覽可修改交易資料、分類、取消勾選與補登；確認匯入不等於已寫入本機／Drive，仍需「儲存變更」。取消預覽不得留下新帳戶。可重命名標籤；已有流水引用的帳戶須先處理流水才能刪除。

解析結果會區分不支持、局部覆蓋、待核對問題及有明確證據的無交易區段。問題數是診斷事件數，不是漏掉的實際交易筆數；成功筆數與沒有警告都不保證整月完整。

## 分類與統計

手動設定優先於自訂關鍵字規則，再使用保守內建建議，否則待確認。規則依列表順序第一條匹配，可限制入帳／出帳。單寫「轉帳」不能證明是自己的帳戶間轉帳，使用者需核對用途。

- 收入分類：薪資、股利、利息、投資回收款、其他收入、未分類。
- 消費分類：沿用信用卡消費分類。
- 不計收支：自有帳戶轉帳、信用卡繳款、投資本金移動及其他排除原因；仍保留流水。
- 待確認：保存紀錄，但不計入收支；Overview 呈現筆數與入出帳金額供回頭核對。
- 收入入帳減收入出帳（沖回）；消費出帳減消費入帳（退款）。不能把銀行退款當薪資或把收入沖回當消費。
- 投資回收款整筆算收入，可能包含本金，**不代表投資收益**；可逐筆或以規則改成其他分類／排除。

Overview同一區塊按幣別展示收入、實際消費、收支差額，以及1／3／6／12個月長條圖／分類占比。實際消費是信用卡淨消費＋確認為消費的銀行淨出帳；排除繳卡費以避免第二次計算。不同幣別不直接相加，收支差額不等於帳戶餘額、淨資產或完整現金流。

無紀錄月份留空，有流水但只有待確認／排除時為觀察到的零收支，均不代表整月完整。圓環只展示正分類淨額占比，零／負分類（退款／沖回較多）保留帶符號表格；完整總額以淨額表格為準。

## 防重複與資料版本

銀行 provenance 使用獨立 `bank-v1:` namespace，來源鍵依文件hash、原始頁／區段／列定位及穩定獨立帳戶id，交易鍵依原始去識別交易內容、方向、幣別、帳戶及同值出現序號。改標籤不改身份；兩戶轉帳的兩邊仍是各自合法流水，去重不等於轉帳對帳。編輯保存原鍵；重映射預覽到不同帳戶需用原始草稿重新建立該帳戶鍵。

精確同文件來源重複略過；跨文件內容相同只能視為疑似重複，需要核對是否保留。沒有銀行交易編號時，無法保證辨別兩次獨立但完全同值的交易。

任一新銀行collection存在（含空陣列）升到v13，所有編輯／背景保存保留新版本及銀行資料。舊版讀者拒讀v13，避免默默刪除新欄位。銀行帳戶及流水id必須唯一、引用完整；不自動補id或引用資產帳戶。

## 密碼與隱私

銀行與信用卡共享目前使用者的加密密碼設定；每組含逗號的已保存密碼視為單一密碼。臨時輸入候選只留記憶體；保存密碼使用AES-GCM密文，金鑰留在瀏覽器IndexedDB，Google帳號與本機scope分開。新裝置／清除網站資料後需重設，帳單內容不發往解析服務。

原始PDF、完整文字頁、餘額、完整帳號欄位、密碼不加入流水JSON或開發日誌。已識別帳號／客戶識別碼在摘要預覽、比對與保存前遮蔽；普通訂單／交易reference數字不盲目刪除。自由文字無法保證完全匿名，摘要或自訂標籤仍可能含個資，請勿輸入完整帳號或身分資料。備份JSON除密碼欄位外不是額外加密的財務資料，勿公開分享。

本機開發中的BANK_PASSWORDS只供授權樣本驗證，不由網站讀取、不設為VITE_變數、不提交或部署。真實對帳單與客戶交易不進Git；回歸使用合成版面與加密PDF。
