# Privacy copy review — source draft, 2026-10-13

This is a technical claim checklist for the current source. It is not a legal opinion or evidence that the updated pages have been published. The public policy's displayed last-updated date remains 2026-10-12 until an actual publication date is known. Its existing in-app notice uses `PRIVACY_UPDATED`; dismissing that notice is not a new consent grant. A later change in Google user-data use needs its own consent review.

| Claim | Current behavior and copy boundary | Evidence |
| --- | --- | --- |
| Financial records | Processed in the browser. Google mode saves JSON in the user's Drive; local mode saves JSON in this browser (IndexedDB, with a localStorage fallback and temporary migration copy). No operator financial-record database. | `src/google/drive.ts`, `src/localStore.ts`, `src/views/Legal.tsx` |
| Backups | A download creates another JSON copy at a user-chosen location. The user must retain and delete it separately. Drive's main file alone is not a full backup because ledger and history live in part files. | `src/App.tsx`, `src/localStore.ts`, `src/views/Legal.tsx` |
| Google token and account hint | The access token is in per-tab `sessionStorage`, persists across reload, normally ends with the tab, but browser session restore may retain it. Account ID, email, name and picture URL remain in `localStorage` as a sign-in hint. Sign-out clears local sign-in state and attempts token revocation. | `src/google/auth.ts`, [MDN sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage) |
| Drive scope | The app currently creates and reads its own folder/files. `drive.file` can also cover files opened with or shared with an app; Wealthline currently has no such selection flow. The scope does not grant whole-Drive access. | `src/google/auth.ts`, `src/google/drive.ts`, [Google Drive scope guide](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) |
| Saved statement passwords | Setting names are plaintext. Passwords are AES-GCM ciphertext in current data, Drive versions and downloaded backups. The nonextractable key stays in this browser's IndexedDB. A new device or cleared site data requires re-entry. Same-browser-profile compromise can still use the key. | `src/statementPasswords.ts`, `src/views/StatementPasswordSettings.tsx` |
| Temporary statement passwords | Temporary card/bank PDF passwords are for the current parsing session and are not saved as settings. | `src/views/BankStatementImport.tsx`, `src/views/Expenses.tsx` |
| External destinations | Google receives authentication and Drive requests. The site's Cloudflare quote relay receives ticker/pair codes and history start dates; market providers receive lookup codes. Cloudflare hosting and third-party services may receive connection metadata. The PDF stays in the browser. | `src/views/Legal.tsx`, `src/quotes.ts`, `src/rates.ts` |
| Deletion effects | Removing current password settings requires a global save and does not erase old backups, Drive versions or browser keys. Local financial-data deletion does not erase downloaded backups or browser keys. Sign-out and Google authorization revocation do not delete Drive files; Drive deletion does not delete downloaded backups. | `src/views/StatementPasswordSettings.tsx`, `src/App.tsx`, `src/localStore.ts`, `src/views/Legal.tsx` |

Reviewed public surfaces: `README.md`, home copy in `src/views/Landing.tsx`, both policy languages in `src/views/Legal.tsx`, `src/site.ts`, the generated home description in `src/prerender.tsx`, `index.html`, and `public/llms.txt`.
