# 信用卡帳單匯入（第一版）

在匯入畫面（自動判斷為信用卡帳單，或舊連結 `/expenses/import`）一次選擇一份或多份 PDF、輸入解密密碼（多組以半形逗號 `,` 分隔）與金額幣別。每份檔案先嘗試無密碼，再依序嘗試已保存並可在此瀏覽器解密的密碼與臨時候選；臨時輸入以逗號分隔並去除前後空白，已保存的每組密碼則保留原值，含逗號視為同一密碼。帳單密碼管理與銀行匯入共享使用者scope，並不以密碼名稱自動配對銀行。PDF.js 在瀏覽器 worker 解密及擷取文字，沒有帳單上傳 API；程式、字元映射與標準字型均由同一網站提供。PDF.js 在選擇檔案或開始解析時才載入。啟動 PDF.js worker 比讀取一份帳單的文字還慢，所以類型判斷、信用卡與銀行解析的各份 PDF 共用一個 worker；取消匯入只結束該次匯入的文件，沒有文件使用時 worker 立即（取消後）或稍後關閉；取消後沒有回應的 worker 不再接新文件，只剩已取消的文件時終止。

入口：信用卡帳單與銀行對帳單共用同一個匯入入口。側欄「收支」底下固定的「匯入帳單」（手機為收支分頁的「匯入」）、「收支總覽」的「匯入帳單」，以及「信用卡消費」「銀行流水」兩頁的匯入按鈕都開啟 `/cashflow/import`；從信用卡或銀行頁開啟時，取消會回到該頁。已在信用卡或銀行帳單匯入畫面時側欄與分頁的入口停用，避免捨棄預覽。入口一律自動判斷，沒有類型切換：信用卡帳單與銀行對帳單可一起選，每份 PDF 只在本機解密、讀取一次：文字層（不做 OCR）判斷類型後，銀行帳單的解析結果、信用卡帳單的文字（匯豐台灣帳單在此時做 OCR）或讀取錯誤直接交給對應分頁，分頁不再重新開檔與解析；判斷時的進度顯示第幾份、檔名與目前步驟。使用者手動指定類型的無法辨識檔案則由該分頁重新讀取。判斷規則（`src/statementKind.ts`）：

- 銀行解析器辨識出已支援的交易表（含已證明無交易的區段）就是銀行帳單。銀行解析器在版型不符時拒絕，不會把信用卡列當成流水。檔案同時有信用卡帳單字樣時仍判為銀行帳單，並在判斷結果提示可另以「信用卡帳單」匯入此檔。
- 認得券商對帳單版面（moomoo 日結單／月結單、台新證券成交憑單／綜合月對帳單；`src/securitiesStatements.ts`）就是證券帳戶對帳單，在銀行判斷之後、信用卡字樣之前。解析時用對帳單自己印的合計交叉核對（各幣別持倉合計、成交合計與筆數、投資組合市值、現金餘額、在途申購贖回）；任何不符都視為部分辨識，不匯入。
- 否則，帳單上有信用卡帳單字樣（「信用卡帳單／電子帳單／對帳單」「本期應繳總（金）額」「最低應繳」「消費日／入帳日」表頭、CREDIT CARD STATEMENT、MINIMUM PAYMENT、DATE／DATE／DESCRIPTION／AMOUNT(幣別) 表頭）就是信用卡帳單。「信用卡繳款」等交易摘要與信用卡廣告不算。
- 三者都不是（包括有銀行名稱但不是已支援交易表的文件、其他券商的證券對帳單、沒有文字的掃描檔）列為「無法辨識」並說明原因，預設不匯入；使用者確定類型時可逐檔改選「以信用卡帳單／銀行帳單匯入」。無法讀取（如密碼錯誤）的檔案同樣列出、不匯入。

全部檔案都辨識成功時直接進入匯入；有無法辨識或無法讀取的檔案時，先留在判斷結果。判斷後仍在 `/cashflow/import`：同一批同時有兩種帳單時分成「信用卡帳單」「銀行對帳單」兩個分頁，兩種同時開始解析，切換分頁不會捨棄預覽；各分頁各自核對、確認匯入或取消，完成的分頁顯示結果並切到尚未完成的分頁，全部完成後列出兩者結果（仍需按「儲存變更」）。上方的「自動判斷結果」列出每份檔案的判斷。本次輸入的密碼與檔案只留在記憶體，離開匯入畫面即清除。

舊連結 `/expenses/import`、`/bank-transactions/import` 仍開啟該類型自己的匯入畫面，略過判斷；畫面上不再提供切換類型。

銀行先從 PDF metadata Title／內文標題辨識，再參考檔名。月份先從帳單標題的民國／西元年月辨識（如 114年11月 → 2025-11），或對照結帳日欄與日期列，再參考檔名 YYYY-MM。一般繳款期限、交易日期、PDF 建立日期不當作帳單月份；銀行／卡片名稱留空時自動辨識，手動填寫會套用到本次全部帳單（可沿用既有卡片名稱）；月份辨識不到時才使用手動備用值。

每份 PDF 依序解析並顯示銀行、月份來源、筆數或失敗原因；一份失敗不阻擋其餘檔案。所有成功結果合併預覽，整批確認前不寫入消費資料。同一銀行多张卡片需要核對預覽的卡片名稱。

解析後可修改銀行／卡片、日期、商家、金額及幣別、取消勾選或補上漏掉的交易。核對未辨識列後，確認匯入，再用既有「儲存變更」保存到本機或使用者自己的 Google Drive。消費不會扣除資產，也不會更改負債。

隨部署提供 PDF.js、CMaps 與標準字型的原始授權於 `/third-party/pdfjs/`，版本固定為 6.4.299。

原始 PDF、明文密碼、完整擷取文字不加入資料檔、不寫日誌。選擇保存的密碼以AES-GCM加密，密文随個人JSON／備份保存，解密金鑰只留在此瀏覽器IndexedDB；新裝置需重新設定。解析完成清除密碼欄位與檔案選擇；取消、換分頁、離開 session 會中止解析。確認的交易及雜湊識別碼才加入財務資料。備份為既有未額外加密的 JSON，勿公開分享。

## 格式範圍

- 文字 PDF，最多 20 MB、100 頁、500,000 字元。
- 交易日期在列首，可為西元／民國完整日期或月／日；第二欄可為入帳日期。沒有年份時，以帳單月份推算跨年。
- 金額在列尾，支援千分位、小數、負號、括號與 CR 退款。已辨識的富邦與玉山臺灣帳單使用最後的臺幣入帳金額，原始外幣金額不另算一筆；SG HSBC 由 AMOUNT(SGD) 自動指定 SGD；台灣匯豐及其他單一金額格式使用指定幣別，臺灣帳單請選 TWD。匯豐樣本能從內文辨識銀行，月份暫以檔名或手動備用值補齊；這些自動辨識結果仍須核對。
- 繳款、上期餘額、應繳總額及多金額不明確欄位不自動匯入。富邦、玉山列尾有多個數字時，需有入帳日期或幣別代碼才視為原幣＋臺幣欄；否則（如誤選的銀行流水：對方帳號／金額／餘額）列入未匯入文字列。整頁掃描圖片、跨行、垂直文字、复杂外幣布局暫不支援。無交易時顯示失敗；部分辨識時顯示未匯入列，不能將解析筆數當成帳單完整性證明。
- 已以使用者提供的富邦、玉山與匯豐樣本在本機驗證解密與文字解析。富邦支援民國日期與商家後方的入帳日期；玉山支援原幣／臺幣雙金額欄。匯豐圖片商家欄以 Tesseract.js 7.0.0 在瀏覽器辨識英文／繁中，先定位「前期餘額／交易明細」以下至本期應繳等摘要前的交易區段，再僅補區段內商家；日期及入帳金額保留文字層原值。定位失敗會拒絕該檔案，避免將整頁日期列當作消費。逐頁處理商家圖片，續頁沿用銀行並可由消費日期／入帳日期表頭定位，所有頁面合併預覽；日期或金額本身只有圖片的全頁掃描仍不支援。信心值低於 65 保留待填商家，OCR 交易（商家已讀到者）預設全部勾選並標示「核對」，使用者取消不要的列；商家讀不到的列仍預設不勾選；載入失敗保留手動預覽，取消會終止 worker；同一次解析的下一份匯豐帳單沿用已載入的 OCR worker，一次只供一份檔案使用。已以真實樣本驗證使用者指出的四筆商家與金額，不保證其他月份或版型完整辨識。
- 證券檔名在讀取前直接拒絕；重新命名的檔案也會檢查解密後的證券對帳單特徵。信用卡廣告單獨提及證券不會被拒絕。真實 PDF、密碼與交易內容均不提交；回歸測試只使用合成資料。

## 去重與資料相容

同一張卡請沿用相同名稱。匯豐使用原始文字列位置，避免 OCR 排除繳款後改變交易序號。每筆保存 PDF 雜湊＋列序號的來源鍵，以及原始日期／商家／金額／幣別／卡片名稱＋同值出現序號的交易鍵。兩者都雜湊後保存，修改預覽或已匯入交易仍保留原始識別碼。確認時再次比對識別碼及修改後交易內容；相同值的多筆交易依出現次數保留。沒有銀行交易編號時，兩張不同帳單上完全相同的獨立交易仍可能被當成重複，請核對預覽。

加入消費至少升為資料格式v10，自訂消費規則至少v11，保存密碼至少v12；存在獨立銀行流水資料時維持v13，信用卡編輯不能降版。讀取保留舊資料相容性，舊版客戶端拒絕不支持的新版本，避免不知情刪掉新增資料。銀行流水不加入此信用卡表格，但Overview以分類後的銀行收入／消費與信用卡淨消費形成統一收支總覽；詳見[銀行對帳單說明](bank-statement-import.md)。

驗證包含合成交易的日期、退款、排除繳款、去重、編輯後重匯入、同值多筆、無效整批拒絕、資料往返與版本保留。加密 PDF 合成樣本的密碼為 `fixture-password`，僅供測試。

OCR worker、WASM 與語言包由 `scripts/prepare-ocr.mjs` 在 dev／test／build 前複製至 `/ocr/7.0.0/`，授權放在其 `licenses/`；不使用 CDN 或外部 OCR API。圖片不寫入資料檔或快取，渲染上限 1600 萬像素，每個辨識工作最多 120 秒。

SG HSBC 文字帳單依 DATE／DATE／DESCRIPTION／AMOUNT(SGD) 表頭讀取交易欄位，支援日＋英文月份與 CR 退款。只取最後的 SGD 入帳金額，不把另列的原幣／國別算為消費；付款、前期餘額與 Total 排除。由 Statement From ... to ... 的結帳日辨識月份，預設卡片名稱為「匯豐 (SG)」。新增六頁樣本在本機驗證為 68 筆消費與 1 筆排除的付款，前期餘額＋交易及付款與帳單總額相符；這個版型不需要 OCR。

## 證券帳戶對帳單（moomoo、台新證券）

同一批可以和信用卡、銀行帳單一起選；分頁多一個「證券帳戶」。現金餘額（每個幣別一筆）與持倉（代號、數量）匯入「帳戶」頁，同名帳戶的持倉整批換成對帳單的內容，確認前先預覽，確認後還要按「儲存變更」。

- 每個帳戶只用日期最新的一份對帳單；較舊的列出但不匯入。匯入的帳戶名稱預設為「moomoo (帳號末四碼)」，可改成既有帳戶名稱以取代其持倉。
- 一般股票代號不帶單價，匯入後由報價更新查價；基金等無法查價的代號帶對帳單的收盤價。
- 只有成交、沒有持倉與餘額的文件（台新證券成交憑單）會列出並說明不匯入；成交紀錄的匯入尚未支援。
- 本機驗證：`node scripts/statement-to-csv.mjs --env-file .env.local <PDF 或資料夾>` 輸出 position／trade／cashflow／in-transit 列，不需啟動前端。
